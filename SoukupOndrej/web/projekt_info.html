Prezentace projektu Flappy Bird

Tato stránka slouží jako rozšířený přehled projektu. Obsahuje podrobné informace o tvorbě dokumentace, uživatelském manuálu, prezentaci pro investora a přehledu pro nového spolupracovníka. Cílem je ukázat, že projekt není pouze jednoduchá hra, ale kompletní aplikace propojující herní klient v Pythonu (pygame), backend ve Flasku, SQLite databázi a webovou část s leaderboardem.

1. Tvorba dokumentace

Dokumentace je důležitou součástí každého softwarového projektu, protože popisuje jeho strukturu, technologické řešení a vzájemné propojení jednotlivých částí. U tohoto projektu je dokumentace důležitá hlavně proto, že aplikace není tvořena pouze jedním souborem, ale skládá se z několika propojených částí: herního klienta, backendu, databáze a webové stránky.

Struktura projektu

Projekt je rozdělen do několika složek. Složka client obsahuje hlavní herní část napsanou v knihovně pygame. Zde se nachází logika pohybu ptáka, generování překážek, vyhodnocení kolizí, počítání skóre a vykreslování grafického rozhraní. Složka server obsahuje backend ve Flasku, který zajišťuje komunikaci s databází, registraci a přihlášení uživatelů a ukládání skóre. Složka web slouží pro webovou prezentaci projektu a zobrazení leaderboardu a dalších informací.

Použitá databáze

V projektu je použita databáze SQLite, protože je jednoduchá, lokální a nevyžaduje samostatný databázový server. Díky tomu je projekt vhodný i pro offline použití a snadné spuštění na jiném počítači. Databáze obsahuje tabulku users, ve které jsou uloženi uživatelé, a tabulku scores, ve které jsou uložena skóre pro jednotlivé obtížnosti.

Tabulka users obsahuje unikátní uživatelské jméno, hash hesla a datum vytvoření účtu. Tabulka scores obsahuje cizí klíč user_id, obtížnost, skóre a datum vytvoření záznamu. Mezi tabulkami je relace 1:N, tedy jeden uživatel může mít více výsledků. Zároveň je v databázi nastaveno omezení, aby se pro jednoho uživatele a jednu obtížnost neukládalo více různých řádků, ale držel se pouze jeden záznam s nejlepším výsledkem.

Propojení klientské hry se serverem

Herní klient komunikuje se serverem pomocí HTTP požadavků. To znamená, že hra přímo nezapisuje do databáze, ale posílá data na backend. Backend tato data zkontroluje, zpracuje a uloží do databáze. Tento přístup je správnější a bezpečnější než přímé připojení hry k databázi, protože server může kontrolovat formát dat a pravidla aplikace.

API komunikace

Backend poskytuje několik API endpointů. Endpoint /api/register slouží pro registraci uživatele, endpoint /api/login slouží pro přihlášení a endpoint /api/scores slouží pro ukládání a načítání skóre. Endpoint /api/health slouží pro kontrolu, zda backend běží správně.

GET /api/health POST /api/register POST /api/login POST /api/scores GET /api/scores?difficulty=normal&limit=10

Návrh jednotlivých částí aplikace

Návrh projektu byl vytvořen tak, aby byly jednotlivé části oddělené a přehledné. Hra je zodpovědná za herní logiku a ovládání. Server je zodpovědný za práci s daty a databází. Webová část slouží pro prezentaci projektu a přehledné zobrazení informací. Díky tomuto rozdělení je projekt přehlednější, lépe rozšiřitelný a vhodný pro další vývoj.

Dokumentace slouží k technickému pochopení projektu a usnadňuje jeho údržbu, testování i další rozšíření. Je užitečná nejen pro autora, ale i pro učitele, spolupracovníka nebo budoucího vývojáře, který by na projektu navázal.

2.Manuál pro uživatele

Instalace prostředí (venv)

Pro správné spuštění projektu je doporučeno použít virtuální prostředí (venv), které oddělí závislosti projektu od ostatních programů v systému.

# vytvoření virtuálního prostředí python -m venv venv # aktivace prostředí (Windows) venv\Scripts\activate # aktivace prostředí (Linux / Mac) source venv/bin/activate

Instalace knihoven

Po aktivaci virtuálního prostředí je potřeba nainstalovat potřebné knihovny.

pip install pygame flask requests

Knihovna pygame slouží pro vykreslování hry, flask pro backend server a requests pro komunikaci mezi hrou a serverem.

Uživatelský manuál je určen pro běžného uživatele, který nemusí znát zdrojový kód ani technické detaily projektu. Jeho cílem je vysvětlit, jak aplikaci spustit, jak se přihlásit, jak hru ovládat, jak ukládat skóre a jak používat webovou část projektu.

Jak aplikaci spustit

Pro spuštění projektu je potřeba mít nainstalovaný Python a požadované knihovny, zejména pygame, flask, requests a pytest pro testy. Nejprve je nutné spustit backend, protože hra i webová část komunikují právě s ním. Backend se spouští souborem server/app.py.

python server/app.py

Po spuštění serveru je možné spustit samotnou hru. Hra se spouští souborem client/main.py.

python client/main.py

Jak se přihlásit

Po spuštění hry se uživateli zobrazí přihlašovací obrazovka. Do prvního pole zadá své uživatelské jméno a do druhého pole heslo. Pokud účet ještě neexistuje, může kliknout na tlačítko Registrovat. Tím se vytvoří nový účet v databázi. Pokud už účet existuje, použije tlačítko Přihlásit.

Po úspěšném přihlášení se uživatel dostane do hlavního menu hry. V menu je zobrazen text s informací, který uživatel je právě přihlášen.

Jak hrát hru

Hra je inspirována známou hrou Flappy Bird. Hráč ovládá ptáka a snaží se prolétat mezi překážkami. Každé úspěšné proletění mezi trubkami zvyšuje skóre. Hra končí při nárazu do překážky, do země nebo do horní části obrazovky.

Ovládání hry je jednoduché:

  • Space nebo kliknutí myší slouží ke skoku ptáka
  • Enter může sloužit k potvrzení některých akcí
  • Esc vrací hráče zpět do menu

Jak ukládat skóre

Po skončení hry se zobrazí obrazovka Game Over. Na ní je vidět aktuální skóre, nejlepší lokální výsledek a přihlášené uživatelské jméno, pod kterým bude výsledek uložen. Uživatel klikne na tlačítko Uložit skóre. Hra následně odešle data na backend, který je uloží do databáze.

Systém je navržen tak, aby se pro jednoho uživatele a jednu obtížnost ukládal jen jeden nejlepší výsledek. To znamená, že pokud uživatel zahraje horší výsledek než dříve, starý lepší výsledek zůstane zachovaný. Pokud zahraje lepší výsledek, starý se přepíše.

Jak používat webovou část projektu

Webová část projektu je dostupná po spuštění backendu v prohlížeči. Uživatel otevře hlavní stránku, kde uvidí leaderboard, tlačítko pro zobrazení vývojového diagramu a další tlačítko pro informace o projektu. Webová stránka načítá skóre ze stejné databáze jako hra, takže výsledky jsou sdílené.

http://127.0.0.1:5000

Díky tomuto manuálu by měl být uživatel schopný aplikaci používat bez znalosti zdrojového kódu. Zvládne ji spustit, přihlásit se, zahrát si, uložit skóre i zobrazit výsledky na webové stránce.

3. Tvorba prezentace pro investora

Prezentace pro investora má za cíl vysvětlit, proč má projekt hodnotu, čím je zajímavý a proč by do něj mělo smysl investovat čas, finance nebo další vývojové kapacity. I když je projekt založen na jednoduché herní myšlence, jeho přínos není jen v samotné hře, ale i v tom, že jde o kompletní systém s backendem, databází, přihlašováním uživatelů, leaderboardem a webovou prezentací.

Proč by měl investor tento projekt koupit nebo podpořit

Projekt ukazuje schopnost vytvořit funkční produkt od začátku do konce. Nejde jen o hru, ale o aplikaci, která propojuje více technologií. Investor v takovém projektu nevidí pouze herní mechaniku, ale hlavně potenciál dalšího rozvoje. Projekt už má základní architekturu, která umožňuje přidávat nové funkce, například více herních módů, online soutěže, rozšířené statistiky, správu uživatelů nebo mobilní verzi.

Hlavní přínosy projektu

  • Projekt spojuje herní logiku, databázi, backend a web do jednoho funkčního celku.
  • Má už implementované přihlášení uživatelů a ukládání výsledků.
  • Je připravený pro další rozšíření, například o achievementy, statistiky nebo další úrovně.
  • Je vhodný jako základ pro vzdělávací, demonstrační i komerčně rozšiřitelný produkt.

Technická hodnota

Investor může ocenit, že už teď je projekt navržen modulárně. Frontend hry je oddělený od backendu, databázová logika je soustředěna v samostatné části projektu a webová stránka je schopná prezentovat výsledky i informace o projektu. Díky tomuto řešení je aplikace připravená na další týmový vývoj.

Možnosti budoucího rozšíření

Hru je možné dále rozvíjet v několika směrech. Lze přidat více druhů překážek, nové herní režimy, grafická vylepšení, ukládání detailnějších statistik nebo propojení s externím serverem. Webovou část lze rozšířit o administraci uživatelů, detailní profily hráčů, historii skóre nebo filtrování výsledků.

Obchodní a prezentační hodnota

Tento projekt může sloužit jako ukázka technických schopností, jako základ pro školní či demonstrační produkt nebo jako prototyp pro větší herní nebo webovou aplikaci. Investor by si tento projekt mohl vybrat proto, že má již hotové jádro a zároveň nabízí jasnou možnost dalšího rozvoje bez nutnosti začínat úplně od nuly.

Pro investora je důležité, že projekt není jen nápad, ale funkční řešení. Je možné ho ihned předvést, vyzkoušet a dále rozšiřovat. To zvyšuje jeho důvěryhodnost a praktickou hodnotu.

4. Tvorba přehledu pro nového spolupracovníka

Tato část je zaměřena na člověka, který se k projektu připojí jako nový spolupracovník a bude na něm dále pracovat. Cílem je, aby z přehledu pochopil, jak funguje kód, jak funguje databáze, jak spolu komunikují jednotlivé části aplikace a kde má začít při dalším vývoji.

Jak funguje kód

Hlavní herní logika je umístěna v souboru client/main.py. Tento soubor obsahuje hlavní smyčku hry, zpracování vstupů z klávesnice a myši, vykreslování herní scény, pohyb ptáka, vytváření trubek, vyhodnocení kolizí a ukládání skóre přes backend. Ve stejném souboru je také řešeno přihlašovací rozhraní a obrazovka Game Over.

Backend je umístěn v server/app.py. Zde se definují API endpointy, které hra i web používají. Tento soubor je zodpovědný za validaci vstupních dat, registraci a přihlášení uživatelů a předávání požadavků do databázové vrstvy.

Databázová logika je soustředěna v server/db.py. Tento soubor obsahuje funkce pro vytvoření databáze, registraci uživatele, vyhledání uživatele, ukládání skóre a načítání leaderboardu. Struktura databáze je definována v souboru server/schema.sql.

Jak funguje databáze

Databáze je SQLite a ukládá se lokálně jako soubor. Obsahuje tabulku users a tabulku scores. Tabulka users uchovává účty uživatelů a tabulka scores uchovává jejich výsledky. Každý výsledek je navázán přes cizí klíč na konkrétního uživatele.

Důležité pravidlo je, že jeden uživatel může mít jen jeden výsledek pro jednu obtížnost. Díky tomu se v leaderboardu neobjevuje stejný hráč několikrát se stejnou obtížností. Pokud hráč získá lepší skóre, databázový záznam se aktualizuje.

Jak spolu komunikují jednotlivé části

Hra komunikuje se serverem pomocí HTTP požadavků. Webová stránka komunikuje se serverem stejným způsobem. Server pracuje jako prostředník mezi klientem a databází. To znamená, že ani hra, ani web se databáze nedotýkají přímo. Všechno jde přes API.

  • Hra odešle login nebo registraci na backend.
  • Backend zkontroluje data a uloží je do databáze.
  • Po dohrání hra odešle score na backend.
  • Backend uloží nebo aktualizuje nejlepší výsledek.
  • Web i hra načítají leaderboard přes stejné API.

Kde začít při spolupráci

Nový spolupracovník by měl nejprve pochopit strukturu složek, pak si projít backend a databázovou vrstvu a teprve potom upravovat herní logiku. Prakticky je dobré začít od `server/schema.sql`, pokračovat přes `server/db.py`, následně přes `server/app.py` a až potom přejít na `client/main.py`.

Na co si dát pozor při úpravách

Při změnách databázové struktury je nutné hlídat, aby odpovídaly i SQL dotazy a API. Při změnách v backendu je nutné myslet na to, že stejná data používá jak hra, tak webová stránka. Při změnách v klientovi je důležité hlídat stavové proměnné hry, například login, menu, ready, playing, gameover a leaderboard.

Tento přehled umožňuje novému spolupracovníkovi rychle pochopit architekturu projektu, orientovat se v souborech, porozumět databázi i API a plynule navázat na další vývoj aplikace.
