🎯 CÍL PROJEKTU

FULL-STACK APLIKACE S AUTENTIZACÍ

Flappy Palach je komplexní demonstrace moderních webových technologií spojených s desktopovou aplikací. Projekt zahrnuje klientskou hru v Pythonu, RESTful API backend v PHP, relační databázi MySQL a responzivní frontend s autentizačním systémem.

🎮 DESKTOPOVÁ HRA

  • Python 3.x + Pygame
  • Fyzikální engine (gravitace, kolize)
  • 3 úrovně obtížnosti
  • Login/Register integrace
  • Real-time API komunikace

🌐 WEBOVÝ FRONTEND

  • Vanilla JavaScript (ES6+)
  • Responzivní CSS Grid/Flexbox
  • Session management
  • AJAX komunikace s API
  • Pixel-art retro design

⚙️ PHP BACKEND

  • 6 REST API endpointů
  • Prepared statements (SQL injection prevence)
  • Password hashing (bcrypt)
  • JSON response format
  • Error handling & validace

💾 DATABÁZE

  • MySQL relační model
  • Foreign key constraints
  • Indexy pro performance
  • ENUM typy pro obtížnost
  • Normalizace (3NF)

📊 DATABÁZOVÝ MODEL (ER DIAGRAM)

TABULKA USERS

  • id – primární klíč (AUTO_INCREMENT)
  • username – unikátní jméno (UNIQUE constraint)
  • password_hash – bcrypt hash hesla
  • date_registered – timestamp registrace
  • last_login – poslední přihlášení

TABULKA SCORES

  • id – primární klíč
  • user_id – cizí klíč na users (CASCADE DELETE)
  • username – denormalizace pro rychlost
  • score – dosažené body
  • difficulty – ENUM('lehka','stredni','tezka')
  • date_created – timestamp pokusu

BEST-SCORE LOGIKA

Systém ukládá pouze nejlepší skóre pro každého uživatele na každé obtížnosti. Při nové hře server porovná skóre s existujícím rekordem – pokud je nové skóre vyšší, starý záznam se smaže a uloží se nový. Tím je zajištěno, že žebříček zobrazuje skutečné TOP výkony bez duplicit.

📊 VÝVOJOVÉ DIAGRAMY

Vizuální znázornění klíčových procesů v aplikaci. Tyto diagramy slouží k rychlému pochopení logiky hry a komunikace mezi komponentami.

DIAGRAM 1: HERNÍ SMYČKA (GAME LOOP)

Hlavní herní smyčka běžící na 60 FPS. Znázorňuje celý cyklus od zpracování vstupu přes fyziku a kolize až po vykreslení a rozhodování o konci hry.

INICIALIZACE

  • Ptáček na střed obrazovky
  • GAP = 200px (startovní mezera)
  • Rychlost trubek = 4.0 px/frame
  • Skóre = 0

FYZIKA & ANIMACE

  • Gravitace (velocity += 0.5)
  • Rotace ptáčka podle rychlosti
  • Mávání křídly při skoku
  • Plynulý pohyb na 60 FPS

STŘÍDÁNÍ PATTERNŮ

  • Pattern 0: Naproti sobě (střed)
  • Pattern 1: Posunuté (nahoru/dolů)
  • Automatické střídání každou trubku
  • Zvyšuje dynamičnost hry

OBTÍŽNOST

  • Každé 3 body → rychlejší
  • GAP se zmenšuje (-3px nebo -6px)
  • Minimální GAP = 120px
  • 3 profily: Lehká, Střední, Těžká

Obr. 1: Vývojový diagram hlavní herní smyčky (60 FPS)

DIAGRAM 2: UŽIVATELSKÝ FLOW (LOGIN → HRA → DATABÁZE)

Kompletní cesta uživatele od spuštění aplikace přes autentizaci, hraní hry až po uložení skóre do databáze. Zobrazuje HTTP komunikaci s backendem a databázovou logiku.

AUTENTIZACE

  • Login/Register formulář
  • Validace (3+ znaky, 4+ heslo)
  • HTTP POST → PHP backend
  • Session management (user_id)

VÝBĚR & HRA

  • Výběr obtížnosti (3 úrovně)
  • Hlavní menu
  • Herní smyčka (ref. Diagram 1)
  • Game Over screen

ODESLÁNÍ SKÓRE

  • HTTP POST submit_score.php
  • Payload: user_id, score, difficulty
  • Server porovná s best-score
  • UPDATE nebo INSERT do DB

DATABÁZOVÁ LOGIKA

  • SELECT best score per difficulty
  • Porovnání nové vs. stávající
  • DELETE starý + INSERT nový
  • CASCADE DELETE při smazání usera
